# 04 — 运行检索评估并比较版本

**What to build:** 让评估管理员可以针对一个知识库同步运行当前已部署 V4 管道，使用共享执行结果计算 Hit Rate@5 和 MRR@5，在全部问题结束后原子保存逐题结果，并按唯一评估版本查看聚合历史。

**Blocked by:** 01 — 提取共享 RAG 执行接口; 03 — 管理标准问题集并标注当前 Chunk

**Status:** resolved

- [x] 评估只加载目标知识库的全部 `ACTIVE` 标准问题，并在没有活动问题时拒绝运行。
- [x] `eval_version` 在单个知识库内唯一且只标记当前部署，不选择管道或覆盖运行参数。
- [x] 同一数据集记录和评估版本具有数据库唯一约束，能够阻止并发重复结果。
- [x] 每个问题只调用一次共享 RAG 执行接口。
- [x] Hit Rate@5 和 MRR@5 使用置信度过滤及上下文裁剪之前的成功 Reranker Top 5。
- [x] 多个期望 chunk 使用排名最靠前的一条；有效未命中贡献 `hit=false` 和 reciprocal rank 0。
- [x] 缺少期望 chunk 时 Hit 和 Rank 保持为空，不进入检索指标分母且不因此标记部分失败。
- [x] 任意 Reranker 降级时保留实际 RRF 回答，全部指标为空，状态为 `PARTIAL`，错误类型为稳定的 `reranker_degraded`。
- [x] 单题主流程异常形成 `FAILED` 结果并继续后续问题。
- [x] 全部问题处理结束后只进行一次结果事务写入；最终写入失败不留下半套版本数据。
- [x] 即使所有问题失败，只要结果保存成功，运行仍返回包含失败数量的成功报告。
- [x] 历史报告按评估时间倒序，包含总数、成功/部分/失败数量、检索样本数、命中数、Hit Rate@5 和 MRR@5，不提供逐题历史接口。
- [x] 每个检索指标只使用非空样本聚合，没有样本时平均值保持为空。
- [x] 测试覆盖版本冲突、无活动问题、命中边界、降级跳过、故障隔离、批量原子保存和历史聚合。
