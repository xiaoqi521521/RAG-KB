# 03 — 管理标准问题集并标注当前 Chunk

**What to build:** 让系统管理员和知识库管理员可以维护带生命周期状态的标准问题集，并查询当前有效 chunk 摘要完成期望证据标注，同时保证知识库权限和 chunk 归属在数据访问层不可绕过。

**Blocked by:** None — can start immediately

**Status:** resolved

- [x] 现有标准问题数据支持 `CANDIDATE`、`ACTIVE`、`NEEDS_REVIEW` 和 `ARCHIVED`，现有记录迁移为 `ACTIVE`。
- [x] 标准问题可以保存可空期望答案、多个全局唯一期望 chunk ID、审核原因和可空唯一反馈来源。
- [x] 系统管理员或目标知识库的本地 `ADMIN` 可以列出、创建、编辑和归档标准问题。
- [x] 公开读权限、`READ` 和 `WRITE` 均不能管理标准问题集。
- [x] 创建的人工标准问题默认为 `ACTIVE`，问题非空且至少具有期望答案或期望 chunk。
- [x] 应用接口不允许客户端提交状态、创建者或反馈来源，也不提供提升为 `ACTIVE` 的操作。
- [x] 已经参与评估的问题不能原地修改；归档保持幂等且不物理删除记录。
- [x] 所有数据集读写同时按知识库 ID 和数据集 ID 过滤，跨知识库访问表现为资源不存在。
- [x] 期望 chunk 可以来自同一知识库的多个文档，但必须属于当前版本、`DONE` 且未删除的文档；任一无效 ID 使整次写入失败。
- [x] 管理员可以查询当前有效 chunk 的文档、位置、Token 和最多 200 字摘要，响应不返回完整正文且首版不分页。
- [x] 权限数据源不可用时拒绝式返回服务不可用，不进入数据集或 chunk 读取。
- [x] 测试覆盖状态、权限矩阵、跨知识库隔离、chunk 归属、已评估记录不可修改和归档行为。
