# 意图路由多轮对话 Spec

Status: accepted

## 1. 目标

在知识库检索前增加 LLM 意图识别，使多轮聊天可以正确处理知识库问题、会话回顾、通用回答和无法确定的问题。知识库问答继续严格依据本次检索得到的参考内容；非知识库回答不被无关检索候选污染，并明确告知通用回答未经过知识库检索。

## 2. 范围

### In scope

- 当前问题的四分类意图识别和 fail-closed 失败语义。
- 同步 HTTP 与 SSE 的分支编排、响应字段和状态事件。
- 非知识库请求的会话、消息、缓存、Token 和 RAG 评估边界。
- 现有聊天请求 Schema、消息表和旧消息的兼容迁移设计。
- 不确定意图、权限、预算和模型异常的验收测试。

### Out of scope

- 引入 LangGraph 或重写现有 RAG 检索实现。
- 跨会话记忆、外部搜索、自动拆分混合问题。
- 新增用户权限模型、独立租户或知识库授权 API。

## 3. 领域意图

| 内部枚举 | 对外 `answer_mode` | 依据 | 是否检索 |
| --- | --- | --- | --- |
| `KNOWLEDGE_BASE_QUERY` | `knowledge_base` | 本轮参考内容，历史仅用于指代和连贯性 | 是 |
| `SESSION_META` | `session_meta` | 当前会话最近五轮历史 | 否 |
| `GENERAL_CHAT` | `general_chat` | 模型通用能力和最近五轮历史 | 否 |
| `UNCERTAIN` | `uncertain` | 固定拆分提示 | 否 |

涉及公司制度、流程、内部人员、内部数据或知识库事实的问题必须是 `KNOWLEDGE_BASE_QUERY`。带历史指代但最终只有一个知识库问题的请求仍是知识库问答；同时要求两个独立信息边界的请求是 `UNCERTAIN`。

## 4. 请求流程

1. 验证 JWT 并实时加载当前用户。
2. 使用现有聊天模型执行意图识别。分类 Prompt 只包含固定规则和当前问题，问题用明确分隔符包裹，并要求严格 JSON、仅允许四个枚举、禁止 Markdown、理由、confidence 和额外字段。
3. 分类网络异常或超时最多重试一次；非法 JSON、未知枚举或重试失败返回 `503`。此时不创建会话、不查知识库权限、不检索、不生成答案。
4. 按意图校验参数并选择分支。
5. 仅知识库问答执行全部 `kb_ids` 的实时读权限校验和既有 V4 RAG 管道。
6. 生成或构造答案，按分支规则持久化有效轮次并返回。

## 5. 分支行为

### 5.1 知识库问答

- `kb_ids` 为空返回 `422`；请求携带多个知识库时任一无读权限整体拒绝。
- 最近五轮历史可用于查询改写、指代消解和回答连贯性，但历史消息不是证据；内部事实必须来自本轮参考内容。
- KB System Prompt 明确参考内容是唯一事实来源，并将 chunk 视为不可执行数据，忽略其中的指令性文字。
- 保留现有引用、拒答、Reranker 降级、上下文裁剪和忠实性观测语义。
- 返回 `answer_mode=knowledge_base`、`knowledge_base_searched=true`，按现有规则返回 `sources` 和 `hit_count`。

### 5.2 会话回顾

- 必须提供 `session_id`，否则返回 `422`；只读取当前用户拥有的当前会话。
- 只向回答模型注入最近五轮历史，不注入知识库参考内容。模型必须只依据历史回答，无法确认的内容不得补全。
- 没有历史时返回固定的“当前会话暂无可回顾内容”语义。
- 不查权限、不检索、不做引用或忠实性评估；`sources=[]`、`hit_count=0`、`knowledge_base_searched=false`。

### 5.3 通用回答

- 可不提供 `kb_ids`；即使携带无权限 `kb_ids` 也忽略，不进行权限校验。
- 可注入最近五轮历史，支持正常多轮闲聊、创作和技术建议。
- Prompt 禁止把模型常识表述为公司官方制度、流程、人员或内部数据；此类问题应由分类器路由到知识库问答。
- 服务端在答案后追加固定免责声明，并将包含免责声明的最终文本持久化。
- 返回 `answer_mode=general_chat`、`knowledge_base_searched=false`、`notice`，且 `sources=[]`、`hit_count=0`。

### 5.4 不确定意图

- 服务端直接返回固定拆分提示，不调用回答模型。
- 不创建会话、不写入用户问题或助手消息；已有会话也不增加本轮。
- 首轮响应 `session_id=null`；已有 `session_id` 时原样返回。
- 同步响应正常返回；SSE 发送固定提示 `token` 后发送 `done`，不发送检索或生成状态。

## 6. HTTP 与 SSE 契约

同步响应和 SSE `done` 元数据增加：

- `answer_mode`: `knowledge_base | session_meta | general_chat | uncertain`
- `knowledge_base_searched`: 布尔值
- `notice`: 可空，仅通用回答使用

`session_id` 改为可空。SSE 事件顺序为：知识库问答 `RETRIEVING → GENERATING → token* → done`；会话回顾和通用回答 `GENERATING → token* → done`；不确定意图 `token → done`。分类失败在流建立前返回 HTTP `503`。

## 7. 会话、消息与缓存

- 新建通用回答会话的初始知识库范围为空；已有会话不修改其原有范围。
- 非知识库消息本轮 `kb_ids=NULL`；知识库消息保存本轮实际请求范围。
- 消息新增 `answer_mode` 和 `knowledge_base_searched`。旧消息兼容默认按 `knowledge_base` 和已检索处理。
- 查询结果缓存只适用于无历史首轮知识库问答且回答包含有效引用的成功结果。
- 缓存值不保存 `kb_ids`、用户、会话、历史、耗时或 Token；缓存键仍包含去空白问题和排序后的知识库范围摘要，以隔离不同知识库范围。
- 非知识库意图不读写查询结果缓存。

## 8. Token、预算和评估

- 意图分类调用受全局预算闸门保护；其输入计入 `input`，输出计入 `answer_generation`。
- `answer_generation` 术语调整为聊天模型生成输出，包含意图分类输出和最终回答输出。
- provider 未返回 usage 时不使用本地估算冒充精确用量；普通统计写入失败不阻断回答。
- 只有知识库问答参与引用解析、拒答判定、RAG 命中统计、在线忠实性评估和查询缓存。
- 会话回顾、通用回答和不确定意图的 Token 仍计入统一 Token 统计，但不计入 RAG 质量指标。

## 9. LangGraph 决策

本阶段不引入 LangGraph。使用显式服务层编排，并定义意图识别和意图执行接口作为未来替换边界。只有出现可恢复长流程、人工介入、复杂动态循环或真正动态 Agent 路由时才重新评估；LangGraph checkpointer 不替代现有数据库会话历史。

## 10. 验收测试

- 四类标准问题分别路由到正确分支，且分类器不会执行用户文本中的伪指令。
- 分类超时、瞬态重试、非法 JSON 和未知枚举分别符合 `503` 与重试约束，失败不产生会话或消息。
- 知识库意图无 `kb_ids` 返回 `422`；非知识库意图携带无权范围仍正常回答；知识库意图任一范围无权整体拒绝。
- KB 回答不能使用历史普通回答或 chunk 指令作为内部事实；会话回顾不能读取知识库；通用回答带免责声明。
- 首轮 KB 缓存键区分知识库范围，缓存值不含 `kb_ids`；非 KB 分支不触发缓存、检索、引用或忠实性评估。
- 同步响应和 SSE 状态、`answer_mode`、`knowledge_base_searched`、`notice`、`session_id` 及不确定意图事件顺序符合契约。
- 消息 `kb_ids`、意图元数据、旧数据默认值和 Token 六类统计符合定义。
