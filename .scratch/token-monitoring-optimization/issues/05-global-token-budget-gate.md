# 05 — 增加全局 Token 预算闸门与单次异常告警

**What to build:** 增加全局每日 Token 预算控制，避免已达到预算后继续启动新的模型调用，并对异常大请求产生可观测告警。预算按 `Asia/Shanghai` 日界线统计，所有在线请求共享；已经开始的请求继续完成。

**Blocked by:** 01 — 建立六类 Token 统计契约与最终回答路径; 02 — 接入 Embedding Token 统计; 03 — 接入 HyDE 与忠实性检测 Token 统计; 04 — 接入 Reranker Token 统计

**Status:** resolved

- [ ] 提供可配置的全局每日 Token 预算，默认 `1,000,000`，时区默认 `Asia/Shanghai`。
- [ ] 在认证、完整知识库读权限和缓存资格判断之后、任何 provider 调用之前执行 Redis 原子预算判断。
- [ ] 已记录当天用量达到预算时拒绝后续新请求，返回可区分的 `429` 预算耗尽响应；不影响已开始请求。
- [ ] 预算达到 80% 产生 Warning，达到 100% 产生 Critical；已开始请求造成的少量超额可被记录。
- [ ] 单次请求实际六类 Token 总量超过 `20,000` 时产生异常告警观测，但不回滚或中断已完成请求。
- [ ] 预算闸门 Redis 读取/原子判断失败返回 `503` 且不调用模型；普通统计写入失败保持非阻断。
- [ ] 不保存请求级 Token 明细，不使用请求 ID或用户 ID作为指标标签。
- [ ] 覆盖预算日界线、80%/100%阈值、并发判断、已开始请求、20,000 Token 超限和 Redis 故障测试。
