# 03 — 同步聊天的首轮缓存与多轮绕过

**What to build:** 将首轮查询缓存接入同步聊天。`POST /api/v1/chat` 必须根据服务端实际加载的会话历史决定资格：新会话或空会话可读写缓存，存在任意历史时跳过读写并继续携带最近五轮历史执行完整 V4 RAG。缓存命中仍保存本轮用户与助手消息、引用和本次完整服务耗时，且本次生成 Token 为 0。

**Blocked by:** 01 — 首轮普通 RAG 查询缓存

**Status:** resolved

- [x] 新会话和无消息会话可以命中 Ticket 01 提供的查询缓存；缓存读取发生在会话历史判定之后。
- [x] 存在任意历史消息时既不读也不写查询结果缓存，模型仍接收既有最近五轮历史和当前问题。
- [x] 缓存命中返回缓存答案与引用，但不复用缓存中的 session ID、Token 用量或 latency；`latency_ms` 为本次完整服务耗时。
- [x] 缓存命中成功保存一对 USER/ASSISTANT 消息，助手消息带缓存引用、当前耗时和 `token_count=0`，保存失败不得产生新的缓存条目。
- [x] 首轮缓存未命中成功后先完成消息持久化，再写入新的可复用缓存；缓存写失败不影响已形成的正常回答。
- [x] 既有同步聊天的拒答、超时、引用和会话所有权语义保持不变。
- [x] 在同步聊天 HTTP/service seam 上覆盖首轮命中、空会话、非空历史绕过、消息持久化、Token 为 0 和完整 latency 行为。
