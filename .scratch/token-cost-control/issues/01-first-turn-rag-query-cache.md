# 01 — 首轮普通 RAG 查询缓存

**What to build:** 为普通 RAG 查询提供跨有权用户复用的首轮查询结果缓存。请求完成实时身份与全部 `kb_ids` 读权限校验后，只有无对话历史的首轮请求才读取缓存；未命中时继续现有 RAG 管道，成功且有引用来源时写入 10 分钟缓存。缓存必须使用规范化当前问题和排序知识库范围生成的 SHA-256 键，拒答、失败和无引用结果不缓存，Redis 读写故障不得阻断正常问答。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] `POST /api/v1/rag/query` 在缓存读取前完成所有请求知识库的实时读权限校验，任一无权范围整体拒绝且不触碰缓存。
- [ ] 相同首轮问题和相同知识库集合可复用答案、引用来源与命中数量；知识库顺序不影响键，问题只去除首尾空白。
- [ ] 内部空白、大小写、标点和语义变化不会被额外归一化；缓存键不包含用户、部门、会话或历史。
- [ ] 缓存 TTL 使用现有查询缓存配置，默认 600 秒；不因文档变更主动失效。
- [ ] 拒答、空引用、生成失败、超时和其他失败结果不写缓存。
- [ ] Redis 读取、反序列化、校验、写入或脏值删除失败按约定降级，不影响未命中后的 RAG 或已生成的正常回答。
- [ ] 缓存日志只记录操作结果和错误类型，不记录问题、缓存键、回答、用户 ID 或知识库 ID。
- [ ] 在普通 RAG HTTP seam 上覆盖权限前置、首轮命中/未命中、键一致性、拒答不缓存和 Redis 故障降级行为。
