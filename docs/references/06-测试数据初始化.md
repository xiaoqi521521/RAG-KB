### hr-handbook.txt
```plain
员工手册 v2.3
人力资源部 2025年修订版

第一章 公司简介

本公司成立于2018年，专注于企业智能化解决方案。公司秉持"技术驱动、用户优先"的理念，
为各行业客户提供AI赋能服务。

第二章 入职流程

2.1 入职第一天

新员工入职第一天，请按以下步骤完成：
1. 8:30前到达前台，凭录用通知书领取工牌
2. 前往IT部领取笔记本电脑，并根据《开发环境配置指南》完成环境搭建
3. 与直属Leader进行30分钟入职对齐会，了解团队和当前工作重点
4. 阅读《代码规范文档》并在HR系统签字确认
5. 完成OA系统账号激活和基础信息填写

2.2 试用期

试用期为3个月。试用期内，直属Leader每月进行一次正式面谈。
试用期结束前2周，由直属Leader提交转正申请。

第三章 假期制度

3.1 年假

员工年假按工龄计算：
- 工作满1年未满10年：5天
- 工作满10年以上：10天
- 工作不满1年：按入职月份折算，每满1个月享有0.4天

年假申请需提前3个工作日在OA系统提交，经直属Leader审批后生效。

3.2 病假

员工因病无法正常工作，需：
1. 当天上午9点前通知直属Leader和HR
2. 病假超过3天需提供医院证明
3. 当年累计病假超过30天，按事假处理

3.3 婚假

员工结婚享有3天婚假。需提前1个月告知HR，并在婚后1个月内提交结婚证复印件。

第四章 绩效考核

4.1 考核周期

公司采用季度考核制度，每季度结束后的第一个月内完成上一季度考核。

4.2 考核维度

绩效考核包含以下维度（满分100分）：
- 工作目标完成情况（60分）
- 工作质量与效率（20分）
- 团队协作与沟通（10分）
- 学习成长与创新（10分）

4.3 考核结果

考核结果分为4个等级：
- 优秀（90-100分）：年终奖金系数1.5
- 良好（75-89分）：年终奖金系数1.2
- 合格（60-74分）：年终奖金系数1.0
- 待提升（60分以下）：需制定改进计划，连续两次将影响晋升

第五章 离职流程

5.1 提交离职申请

员工需提前30天在OA系统提交离职申请，经直属Leader和HR审批。

5.2 工作交接

离职员工需在最后工作日前完成：
1. 文档整理和知识沉淀（代码、设计文档、操作手册等）
2. 与接任同事完成面对面工作交接
3. 归还公司设备（电脑、门禁卡等）
4. 财务结清（报销款、借款等）
```

### tech-spec.txt
```plain
技术规范文档 v1.4
技术委员会 2025年修订版

第一章 代码规范

1.1 提交规范

所有代码提交必须遵循以下Commit Message格式：
type(scope): message

type 类型：
- feat：新功能
- fix：Bug修复
- docs：文档修改
- refactor：重构（不影响功能）
- perf：性能优化
- test：测试相关
- chore：构建工具、依赖等变更

示例：
feat(payment): 新增微信支付接口
fix(order): 修复订单金额计算精度问题

1.2 分支策略

主要分支：
- main：生产环境代码，只接受来自 release 分支的 PR
- develop：开发主分支，日常开发在此分支基础上创建特性分支
- feature/xxx：特性开发分支，从 develop 创建，完成后 PR 到 develop
- hotfix/xxx：紧急修复分支，从 main 创建，完成后同时 PR 到 main 和 develop

代码审查规则：
- 所有 PR 至少需要 2 名同事 approve
- 禁止直接 push 到 main 和 develop 分支

第二章 接口规范

2.1 RESTful 接口设计

接口设计遵循 RESTful 规范：
- GET：查询数据，幂等，不修改服务端状态
- POST：创建资源
- PUT：全量更新资源
- PATCH：部分更新资源
- DELETE：删除资源

URL 规范：
- 使用名词复数：/api/users, /api/orders
- 版本号在 URL 中：/api/v1/users
- 禁止使用动词：/api/getUser（错误），应为 GET /api/users/{id}

2.2 响应格式

统一响应格式：
{
  "code": 200,
  "message": "success",
  "data": {},
  "traceId": "abc123"
}

错误码规范：
- 200：成功
- 400：请求参数错误
- 401：未认证
- 403：无权限
- 404：资源不存在
- 429：请求过于频繁（限流）
- 500：服务器内部错误

2.3 API 限流策略

为保护后端服务，所有 API 接口均实施限流：
- 单用户每分钟最多100次调用
- 采用滑动窗口算法，比固定窗口更精确
- 超出限制返回 HTTP 429，响应头包含 Retry-After 字段
- AI 相关接口（大模型调用）单独限流：单用户每分钟10次

第三章 数据库规范

3.1 命名规范

- 表名：下划线分隔，复数，如 user_orders
- 字段名：下划线分隔，如 created_at
- 主键：统一命名为 id，BIGSERIAL 类型
- 时间字段：created_at, updated_at, deleted_at

3.2 必须包含的字段

所有业务表必须包含：
- id: BIGSERIAL PRIMARY KEY
- created_at: TIMESTAMP NOT NULL DEFAULT NOW()
- updated_at: TIMESTAMP NOT NULL DEFAULT NOW()
- is_deleted: BOOLEAN NOT NULL DEFAULT FALSE（软删除）

3.3 索引规范

- 每个查询高频字段必须建索引
- 软删除字段添加条件索引：WHERE is_deleted = FALSE
- 联合索引遵循最左匹配原则
- 禁止在生产环境直接 DROP INDEX（先 CONCURRENTLY 创建新索引再删旧的）

第四章 安全规范

4.1 认证鉴权

- 所有 API 必须通过 Sa-Token JWT 认证
- Token 有效期不超过 24 小时
- 敏感操作（删除、支付等）需要二次验证

4.2 SQL 注入防护

- 禁止拼接 SQL 字符串，全部使用参数化查询
- ORM 框架（JPA/MyBatis）的动态查询必须使用预编译语句
- AI 系统中模型生成的参数，必须经过白名单校验后才能传入查询

4.3 敏感数据处理

- 密码必须使用 BCrypt 加密存储
- 手机号、身份证等 PII 数据，展示时进行脱敏处理
- 禁止在日志中打印完整的敏感信息
```

### product-faq.txt
```plain
产品FAQ文档
产品部 2025年Q4版本

Q1: 如何开始使用产品？

A: 注册账号后，系统会自动为您创建一个默认工作空间。
完成以下步骤即可开始使用：
1. 在个人设置中完善账号信息
2. 进入控制台，选择您需要的功能模块
3. 参考《快速入门指南》完成初始化配置

Q2: 免费版和付费版有什么区别？

A: 免费版功能限制如下：
- AI问答：每日100次
- 知识库文档：最多50个
- 存储空间：1GB
- 不支持API接入

付费版（专业版）：
- AI问答：每日10000次
- 知识库文档：无限制
- 存储空间：100GB
- 支持API接入，每日1000次API调用
- 优先客服支持

Q3: 如何申请API访问权限？

A: 申请API访问权限步骤：
1. 登录控制台，进入「开发者中心」
2. 点击「创建API Key」，填写用途说明
3. API Key立即生效，免费配额：每日1000次调用
4. 如需更高配额，可在「套餐管理」中升级付费套餐

API调用频率限制：
- 免费版：每分钟10次，每日1000次
- 付费版：每分钟100次，每日10000次

Q4: 数据安全如何保障？

A: 我们采用多层次的数据安全保障机制：
1. 传输安全：全程HTTPS加密，防止中间人攻击
2. 存储安全：数据加密存储，密钥定期轮换
3. 访问控制：基于角色的权限管理（RBAC），最小权限原则
4. 数据隔离：多租户架构，不同用户数据完全隔离
5. 备份机制：每日自动备份，保留30天，支持时间点恢复

Q5: 知识库支持哪些格式的文档？

A: 目前支持以下格式：
- PDF（包含扫描件，支持OCR识别）
- Word文档（.docx格式）
- Markdown文件（.md格式）
- 纯文本文件（.txt格式）

单个文件大小限制：50MB
建议文档在100页以内，过大的文档建议拆分上传

Q6: AI回答不准确怎么办？

A: 如果发现AI回答不准确，可以：
1. 点击答案下方的「不好用」按钮，留下反馈
2. 检查知识库文档是否包含该问题的答案
3. 尝试换个方式提问，更具体的问题通常效果更好
4. 如果知识库文档有更新，记得重新上传最新版本

我们会根据用户反馈持续优化AI模型，您的反馈非常重要。
```
