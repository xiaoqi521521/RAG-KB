## 执行步骤

### 1. 定位 data.sql

确认文件存在：

```text
app/db/data.sql
```

用户已说明该文件已存放，本次未修改该文件。

### 2. 检查 PostgreSQL 表是否存在

命令逻辑：

```python
select current_database(),
       to_regclass('public.kb_knowledge_base'),
       to_regclass('public.kb_eval_dataset');
```

结果：

```text
('ragkb', 'kb_knowledge_base', 'kb_eval_dataset')
```

说明：

- 已连接到数据库 `ragkb`。
- `kb_knowledge_base` 表存在。
- `kb_eval_dataset` 表存在。

### 3. 检查测试数据是否已初始化

命令逻辑：

```sql
select count(*) from kb_knowledge_base;
select count(*) from kb_permission;
select count(*) from kb_eval_dataset;
```

结果：

```text
kb_knowledge_base=4
kb_permission=5
kb_eval_dataset=5
```

判断：

- 以上数量与 `data.sql` 中的初始化数据一致。
- 因为 `kb_permission` 存在 `(kb_id, subject_type, subject_id)` 唯一约束，重复执行 `data.sql` 会导致唯一约束冲突。
- 因此本次未重复执行 `data.sql`，判定数据库测试基础数据已完成初始化。

### 4. 验证测试文档文件

命令：

```powershell
Get-ChildItem tests\resources\test-docs -File | Select-Object Name,Length
```

结果：

```text
hr-handbook.txt   2629
product-faq.txt   2399
tech-spec.txt     3506
```

## 验证结论

- `app/db/data.sql` 已存在，且未被修改。
- 数据库 `ragkb` 可连接。
- 基础测试数据已存在，数量与 `data.sql` 对齐。
- 3 个测试文档已生成到 `tests/resources/test-docs/`。

## 后续说明

如果需要强制重新执行 `data.sql`，需要先清理相关测试数据，至少包括：

```sql
truncate table kb_permission restart identity;
truncate table kb_eval_dataset restart identity;
truncate table kb_knowledge_base restart identity;
```

当前不建议直接重跑，因为会影响现有数据库内容。
