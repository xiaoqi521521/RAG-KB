## TDD 过程

先写测试：

- `test_settings_loads_required_rag_defaults`
- `test_current_user_contextvar_is_set_and_reset`
- `test_fastapi_health_endpoint`

首次执行：

```powershell
uv run pytest tests/test_initialization.py -v
```

结果：3 个测试均失败，失败原因是 `ModuleNotFoundError: No module named 'app'`。这是预期的 RED 状态，说明测试先于实现建立了目标接口。

随后补充最小实现，再次执行测试时遇到两个初始化问题：

1. 环境中存在 `DEBUG=release`，导致 `debug: bool` 解析失败。
   - 处理：配置字段改为读取 `APP_DEBUG`，避免和系统环境变量冲突。

2. `prometheus-fastapi-instrumentator` 当前版本在测试环境中与 FastAPI 路由结构触发兼容问题。
   - 处理：新增 `ENABLE_METRICS=false`，metrics 默认关闭，后续监控专项再单独开启并验证。

最终初始化测试通过。

## 注意事项

- 当前是项目初始化骨架，不包含业务模型、数据库迁移、真实 JWT 校验和完整 RAG 查询实现。
- `ContextVar` 只用于请求上下文传递，权限安全仍必须在 Repository SQL 中通过 `tenant_id` / `kb_id` 硬过滤。
- ChatOpenAI 和 OpenAIEmbeddings 只有在提供 `OPENAI_API_KEY` 或 `DASHSCOPE_API_KEY` 时才初始化。
- Metrics 默认关闭，后续实现监控章节时应开启 `ENABLE_METRICS=true` 并补充专项测试。
- 测试运行产生了 `__pycache__` 缓存目录；清理命令因审批系统返回 503 被拒绝，本次未继续尝试删除。
