## 执行范围

本次根据 `docs/specs/08-文档切分spec.md` 实现文档切分层。

In scope：

- 新增文档切分服务模块。
- 新增 `ChunkSplitter` 切分器接口。
- 新增递归字符切分器。
- 新增结构感知切分器。
- 新增 chunk 配置校验和异常类型。
- 新增 chunk metadata 标准化逻辑。
- 新增单元测试覆盖 spec 主要验收场景。

Out of scope：

- 不调用 Embedding。
- 不写入数据库。
- 不生成 `chunk_id`。
- 不访问 MinIO。
- 不实现向量检索。
- 不实现 Token 预算裁剪。
- 不引入 LLM 或外部语义服务做分块。


查询结论：

- LangChain Python 官方文档推荐 `RecursiveCharacterTextSplitter` 作为通用文本切分器。
- 标准导入方式：

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter
```

- 常用参数包括：

```python
RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200,
)
```

- 官方示例中可通过 `split_documents(docs)` 切分 `Document` 列表，也可以围绕 splitter 封装项目自己的业务 metadata 规则。
- 官方示例提到 `add_start_index=True` 可把每个 split chunk 在原始文档中的起始字符偏移写入 metadata，字段名为 `start_index`。本项目 spec 明确不把 `start_index` 放入输出 metadata，所以本次未启用。

## 核心实现

### ChunkConfig

使用 dataclass 定义切分配置。`ChunkConfig` 自身保留兜底默认值：

```plain
chunk_size=512
chunk_overlap=64
min_chunk_chars=20
structure_aware=True
```

`ChunkConfig.from_settings(...)` 会从项目 `Settings` 读取：

```plain
RAG_CHUNK_SIZE -> settings.rag_chunk_size
RAG_CHUNK_OVERLAP -> settings.rag_chunk_overlap
```

当前 `.env.example` 已包含：

```plain
RAG_CHUNK_SIZE=512
RAG_CHUNK_OVERLAP=64
```

如果配置文件未提供这两个环境变量，则使用 `Settings` / `ChunkConfig` 中的默认值。`ChunkService.split_documents(...)` 调用时如果没有显式传入 `ChunkConfig`，会默认使用 `ChunkConfig.from_settings()`。

校验规则：

- `chunk_size > 0`
- `chunk_overlap >= 0`
- `chunk_overlap < chunk_size`
- `min_chunk_chars >= 0`

非法配置抛出 `ChunkConfigError`。

### ChunkSplitter

新增切分器接口：

```python
class ChunkSplitter(Protocol):
    @property
    def strategy_name(self) -> str:
        ...

    def split(self, doc: Document, config: ChunkConfig) -> list[Document]:
        ...
```

职责边界：

- 只负责单个 `Document` 的局部切分。
- 负责输出 `split_strategy`、`estimated_tokens`、`page_num` 和可选 `section_title`。
- 不负责全局 `chunk_index`。
- 不负责跨文档合并、Embedding、入库或外部服务调用。

### RecursiveCharacterChunkSplitter

职责：

- 处理无结构文本。
- 处理结构章节过长时的兜底切分。
- 使用 LangChain `RecursiveCharacterTextSplitter`。

默认分隔符：

```python
["\n\n", "\n", "。", "！", "？", "；", "，", " ", ""]
```

### StructureAwareChunkSplitter

职责：

- 消费文档加载阶段已经写入的 `section_title`。
- 不重新解析 Markdown `#`、Word 标题样式或 MinerU 原始结构。
- 当章节长度不超过 `chunk_size` 时，直接保留整个 `Document` 为 1 个 chunk。
- 当章节过长时，在章节内部调用递归字符切分，并保留 `page_num`、`section_title`。

### ChunkService

职责：

- 接收 `list[Document]`。
- 根据 `structure_aware` 配置和 `section_title` 是否存在选择切分器。
- 未显式传入 `ChunkConfig` 时，调用 `ChunkConfig.from_settings()` 获取默认配置。
- 过滤空白文本和短碎片。
- 汇总所有局部 chunk 后重新分配全局 `chunk_index`。
- 收敛输出 metadata，只保留：

```plain
chunk_index
split_strategy
estimated_tokens
page_num
section_title（输入存在时）
```

## Token 估算

本阶段不依赖外部 tokenizer，按 spec 使用轻量估算：

```plain
中文字符：约 1.5 Token
非空白非中文字符：约 0.3 Token
```

实现中使用 `math.ceil(...)` 返回整数，避免出现 0.x 这类不便于后续统计的值。

## Review 关注点

- 当前 `ChunkService` 默认只内置两个切分器；后续新增语义切分、表格切分时可继续通过 `ChunkSplitter` 接口接入。
- 当前不启用 LangChain `add_start_index=True`，因为它会额外写入 `metadata["start_index"]`，而 spec 明确 `start_index` 不进入 chunk metadata。
- 当前 `chunk_size` 和 `chunk_overlap` 由 `ChunkConfig.from_settings()` 从 `Settings` / `.env` 读取；只有调用方显式传入 `ChunkConfig` 时才覆盖项目配置。
- 当前 `section_title` 只在输入存在时输出；TXT 等无章节文档不会写入空字段。
- 当前 `estimated_tokens` 是粗略估算，精确 Token 控制应留给后续上下文裁剪层。
