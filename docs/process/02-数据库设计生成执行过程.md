## 关键处理

1. 将原 Spring 项目中的 `schema.sql` 迁移为 Python 项目结构下的 `app/db/schema.sql`。
2. 保留 PostgreSQL + PGVector 设计，初始化 SQL 中包含：
   - `CREATE EXTENSION IF NOT EXISTS vector;`
   - `kb_knowledge_base`
   - `kb_permission`
   - `kb_document`
   - `kb_doc_chunk`
   - `kb_index_task`
   - `kb_chat_session`
   - `kb_chat_message`
   - `kb_answer_feedback`
   - `kb_eval_dataset`
   - `kb_eval_result`
3. `kb_doc_chunk.embedding` 使用 `VECTOR(1024)`，对齐 `text-embedding-v3` 向量维度。
4. `kb_doc_chunk.content_tsv` 使用 `TSVECTOR`，并在 SQL 中保留全文检索触发器。
5. 实体类使用 SQLAlchemy 2.0 的 `Mapped` / `mapped_column` 写法。
6. `VECTOR(1024)` 使用 `pgvector.sqlalchemy.Vector` 映射，确保 Python `list[float]` 可被正确绑定为 PostgreSQL vector 参数；`TSVECTOR` 保留轻量自定义 SQLAlchemy 类型。
7. `kb_chat_message.sources` 使用 PostgreSQL `JSONB`。
8. `kb_eval_dataset.expected_chunk_ids` 使用 PostgreSQL `BIGINT[]`。
9. `IndexTask` 保留 `can_retry()` 行为。
10. 在 `app/core/config.py` 增加 `env_ignore_empty=True`，避免 `.env` 中留空配置覆盖默认值导致测试启动失败。

## 新增类的解释

本次新增的实体类集中在 `app/models/kb.py`，用于把 `app/db/schema.sql` 中的数据库表映射为 SQLAlchemy ORM 模型。类的职责如下：

### 自定义数据库类型

- `TSVector`：映射 PostgreSQL 的 `TSVECTOR` 类型，用于 `kb_doc_chunk.content_tsv` 字段，承接全文检索索引。
- `PGVector`：来自 `pgvector.sqlalchemy.Vector`，映射 PGVector 的 `VECTOR(n)` 类型，本项目用于 `VECTOR(1024)`，对应 `kb_doc_chunk.embedding` 字段。

`TSVector` 只负责让 SQLAlchemy 能识别 PostgreSQL 专有全文检索类型，不包含业务逻辑。`PGVector` 使用官方 Python 类型，除生成 `VECTOR(1024)` DDL 外，还提供 bind/result processor，避免写入向量时把 Python list 直接传给 asyncpg。

### 枚举类

- `PermissionSubjectType`：权限主体类型，包括部门和用户。
- `KbPermissionLevel`：知识库权限级别，包括读、写、管理员。
- `DocumentStatus`：文档索引状态，包括待处理、处理中、完成、失败。
- `IndexTaskType`：索引任务类型，包括首次索引和重建索引。
- `IndexTaskStatus`：索引任务执行状态，包括待处理、运行中、完成、失败。
- `ChatMessageRole`：对话消息角色，包括用户和助手。

当前数据库字段仍使用 `VARCHAR` 保存枚举值，没有创建 PostgreSQL enum 类型，目的是保持初始化 SQL 简单，并与参考项目的字符串枚举设计对齐。

### ORM 实体类

- `KnowledgeBase`：映射 `kb_knowledge_base`，表示一个知识库，包含名称、描述、归属部门、公开状态、创建人和软删除标记。
- `KbPermission`：映射 `kb_permission`，表示知识库授权关系，用于记录部门或用户对某个知识库的读、写、管理权限。
- `KbDocument`：映射 `kb_document`，表示上传到知识库的原始文档，记录文件信息、MinIO 路径、索引状态、chunk 数量、token 数量和文档版本。
- `DocChunk`：映射 `kb_doc_chunk`，表示文档切分后的最小检索单元，包含原文、全文检索向量、embedding 向量、页码、章节标题和文档版本。
- `IndexTask`：映射 `kb_index_task`，表示异步索引任务，记录任务状态、重试次数、错误信息和执行时间，并保留 `can_retry()` 判断是否还能重试。
- `ChatSession`：映射 `kb_chat_session`，表示一次多轮问答会话，记录用户、关联知识库列表、标题、消息数和最后活跃时间。
- `ChatMessage`：映射 `kb_chat_message`，表示会话中的单条消息，记录用户或助手内容、引用来源、token 消耗、耗时和反馈。
- `AnswerFeedback`：映射 `kb_answer_feedback`，表示用户对助手回答的点赞、点踩和文字反馈。
- `EvalDataset`：映射 `kb_eval_dataset`，表示 RAG 评估问题集，记录问题、期望答案和期望命中的 chunk ID。
- `EvalResult`：映射 `kb_eval_result`，表示一次 RAG 评估结果，记录命中情况、排名、实际答案和 RAGAS 指标。

这些实体类目前只承担数据映射职责，不包含 Repository、Service 或 API 行为。后续业务逻辑应放在 `repositories/` 和 `services/` 中，避免把检索、权限、索引流程直接写进 ORM 模型。

## 备注

- 本次只生成初始化 SQL，不自动执行建表。
- 真实 PostgreSQL 初始化时，需要先确认目标数据库可连接，并手动执行 `app/db/schema.sql`。
- 后续如果引入 Alembic，建议将 `app/db/schema.sql` 作为完整结构快照，同时在 `app/db/migrations/` 或 Alembic 默认目录中维护增量迁移。
