- **项目描述**：
  基于 RAG 架构构建的企业内部知识库问答系统，支持多部门知识库隔离、文档上传与智能索引、多轮对话流式问答。用户上传企业文档（PDF / Word / Markdown / TXT），系统自动解析、分块、向量化存入 PGVector，用户提问时通过混合检索 + 精排 + 生成完成回答并标注引用来源。
- **个人职责**：

  - 向量检索（PGVector 余弦相似度）与 PostgreSQL 原生全文检索并行召回，**RRF 融合排序**后送入 **Cross-Encoder Reranker 精排**，Top-K 动态调整；相比纯向量检索，**Hit Rate 提升约 20%**
  - 构建 **Embedding 缓存 + 查询结果缓存 + Context Token 裁剪** 三重 Token 成本控制机制，通过 Redis 复用向量化结果与高频查询结果，并按 Token 预算动态裁剪检索上下文，在保证回答质量的同时控制单次请求成本与延迟
  - SSE 流式返回生成内容，**每条回答标注引用来源**，支持**回答忠实性评估与幻觉检测**；前端实时渲染 Markdown，流式完成后自动替换引用标记为实际文档名
  - 数据权限从 Prompt 约束升级为代码硬保证，**权限校验不仅在 API 层做拦截，检索阶段也做 Chunk 级别过滤**，在 Chunk 检索阶段强制过滤用户无权访问的知识库的 Chunk，从数据层面杜绝跨部门信息泄露。
  - **Embedding、Reranker、HyDE、幻觉检测、回答生成**——每个 Token 消耗环节独立埋点，按用户维度持久化到 Redis，前端监控面板实时展示各环节消耗分布
  - 构建评估数据集（问题 + 期望命中 Chunk ID+ 期望答案），自动计算 **Hit Rate、MRR、Faithfulness 等指标**，每次调整分块策略或检索参数后跑评估对比，用数据驱动优化而非凭感觉调参
