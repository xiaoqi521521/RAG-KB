# 17-引用溯源与防幻觉校验 Plan

本文基于 [17-引用溯源与防幻觉校验.md](../references/17-引用溯源与防幻觉校验.md)、当前 V4 RAG 查询管道以及本次设计访谈形成。本文只描述后续实施方案，不包含代码实现。

本阶段目标是在现有“查询改写 → 混合检索 → RRF → Reranker → Token 裁剪 → 回答生成”链路上补齐两类能力：

- 让回答中的事实能够映射到具体文档、页码、章节和 chunk。
- 抽样评估回答是否忠实于参考内容，为后续质量治理提供数据，但不让评估模块影响主链路可用性。

## 1. 当前状态与缺口

当前项目已经具备以下基础：

- `RagQueryServiceV4` 已完成 HyDE、混合检索、Reranker、置信度过滤和上下文裁剪。
- `SourceBuilder` 会给进入 Prompt 的 chunk 编号，并保留文档、知识库、页码、章节和 chunk 元数据。
- 无召回、低置信度、空上下文时会直接返回固定拒答。
- Prompt 已要求模型基于参考内容回答，并支持基础 `[参考N]` 标记。
- `TokenMetrics` 已能记录生成 Token，OpenTelemetry 基础设施已存在。

仍存在以下缺口：

- `sources` 在生成前构建，无法根据模型实际引用筛选来源。
- 没有独立引用解析器，组合引用、重复引用和越界编号没有明确行为。
- `SourceCitation` 缺少回答引用编号和来源摘要，前端需要依赖数组位置推断。
- V4 没有独立的严格引用 Prompt，当前共享 Prompt 不能要求每条事实标注来源，也没有强调流程和列表完整性。
- 没有忠实性评估服务、抽样配置、独立超时、失败状态和指标。
- 默认查询管道已切换为 `v4`，完整的引用溯源和忠实性观测能力会在新部署中生效。

## 2. 已确认的设计决策

| 主题 | 已确认方案 |
| --- | --- |
| 主链路保障 | 确定性拒答规则负责阻断；忠实性评估首版只做抽样观测，不自动拦截答案 |
| 无引用标记 | 正常回答完全未标注引用时，返回全部实际参考 chunk，不增加模型或 Embedding 调用 |
| 混合有效与无效编号 | 忽略无效编号，只返回有效编号对应的来源 |
| 全部编号无效 | 正常返回回答，`sources` 为空，并记录警告与指标 |
| 明确拒答 | 返回固定拒答，`sources=[]`、`hit_count=0`，不执行引用兜底和忠实性评估 |
| 引用展示 | `answer` 保留引用标记，不新增纯文本答案字段 |
| 标准格式 | `（来源：[参考1]）`；多来源为 `（来源：[参考1][参考2]）` |
| 兼容格式 | 解析器兼容现有裸标记 `[参考N]`，不支持更多任意格式 |
| 来源字段 | 新增 `reference_index` 和最多 200 字符的 `excerpt` |
| 回答完整性 | 普通回答保持简洁；流程、步骤、编号、条件列表必须按参考内容完整列出，不得空泛概括 |
| 忠实性抽样 | 抽样率可配置，默认 `0.2`；`0` 关闭，`1` 全量执行 |
| 评估失败 | 超时、异常或解析失败记为 `error`，分数为空，不重试、不阻断回答 |
| 评估超时 | 独立超时默认 5 秒，可配置 |
| 评估模型 | 复用当前回答模型，不新增模型客户端和密钥配置 |
| 对外响应 | 不向用户返回忠实性分数，仅保留现有回答结构和新增来源字段 |
| 数据持久化 | 本阶段不写数据库，只记录日志、指标和额外生成 Token |
| 管道版本 | 在现有 V4 内完善，不新增 V5 |
| Prompt 边界 | 新严格 Prompt 只用于 V4，V1-V3 保持现有行为 |
| 默认管道 | 实施完成后将 `rag_query_pipeline` 默认值切换为 `v4` |

相关领域语言和架构取舍记录在：

- [CONTEXT.md](../../CONTEXT.md)
- [ADR-0001：无引用标记时返回全部参考内容来源](../adr/0001-fallback-to-all-context-sources.md)
- [ADR-0002：在 V4 管道内演进回答质量保障](../adr/0002-evolve-v4-with-answer-quality-guards.md)

## 3. 业务范围

### 3.1 In Scope

- 为 V4 增加独立引用 Prompt。
- 解析单个、组合、重复和裸格式引用标记。
- 按回答中的有效引用编号筛选来源。
- 实现无标注、部分无效、全部无效和明确拒答四类来源分支。
- 在来源中增加 `reference_index` 和 `excerpt`。
- 抽样执行忠实性评估。
- 为忠实性评估增加独立超时、错误状态和可观测指标。
- 记录忠实性评估额外消耗的生成 Token。
- 将默认查询管道切换为 V4。
- 增加引用解析、来源构建、忠实性评估、V4 编排、配置和 API 行为测试。
- 同步更新第 17 章相关设计文档。

### 3.2 Out of Scope

- 不做逐句 Embedding 来源匹配。
- 不做引用修复、回答重写或额外生成重试。
- 不因忠实性评估判定不通过而自动拦截答案。
- 不新增独立评估模型、客户端、API Key 或模型路由。
- 不把忠实性结果写入数据库。
- 不实现前端来源卡片、SSE 流式输出、多轮会话或消息持久化。
- 不调整权限校验位置和检索层硬过滤。
- 不修改 HyDE、混合检索、RRF、Reranker、置信度过滤和 Token 裁剪算法。
- 不新增公开 Controller 或查询路径。

## 4. 目标查询流程

```plain
用户问题
  -> 权限校验
  -> HyDE + 混合检索 + RRF
  -> Reranker，失败时沿用现有降级
  -> 置信度过滤
  -> Token 预算裁剪
  -> 构建带 [参考N] 编号的 context 和全部候选来源
  -> 使用 V4 专用引用 Prompt 生成回答
  -> 如果模型明确拒答：返回固定拒答和空来源
  -> 解析回答中的引用编号
  -> 按引用分支筛选或兜底来源
  -> 按配置决定是否抽样执行忠实性评估
  -> 记录评估状态、分数、耗时和 Token
  -> 返回 answer + sources + hit_count + latency_ms
```

引用解析和忠实性评估都只能处理已经经过权限过滤的参考内容，不得重新检索或扩大知识库范围。

## 5. 模块设计

### 5.1 V4 引用 Prompt

建议新增独立 Prompt 模块，例如：

```plain
app/services/rag_prompt.py
```

该模块只负责根据 `context` 和参考条目数量构建 V4 System Prompt，不承载权限、引用解析、评估或拒答编排。

Prompt 必须明确：

1. 只能根据参考内容回答，不使用模型自身知识补全公司制度。
2. 每条事实后使用标准引用格式 `（来源：[参考N]）`。
3. 同一事实有多个来源时连续列出多个编号。
4. 参考内容不足时明确回答“在知识库中未找到相关内容”。
5. 禁止使用“通常情况下”“根据我的了解”等推测性表达。
6. 参考内容存在步骤、列表、编号或条件时，按原顺序完整列出实际可见条目。
7. 不得用“按规定流程操作”等空泛概括替代具体步骤。
8. 如果上下文因 Token 预算只保留部分内容，只回答可见内容，不声称流程完整。

V1-V3 继续使用当前共享 Prompt，避免旧管道行为随本阶段发生变化。

### 5.2 CitationParser

建议新增：

```plain
app/services/citation_parser.py
```

职责：

- 从回答中提取 `[参考N]` 编号。
- 同时支持标准来源说明和现有裸标记。
- 支持一个来源说明中连续出现多个编号。
- 对重复编号去重，并保持首次出现顺序。
- 只负责语法提取，不访问数据库，不判断 chunk 是否存在。

解析器输出原始编号列表，编号是否有效由来源构建阶段根据本次参考内容数量判断。

解析规则保持收敛：允许标记内部少量空白差异，但不支持英文 `ref`、文档名引用或其他任意格式，避免错误匹配普通文本。

### 5.3 SourceBuilder 扩展

保留当前 `SourceBuilder.build()` 的基础职责：

- 按排序后的 chunk 构建 `[参考N]` context。
- 生成与编号一致的全部候选来源。
- 遵守现有上下文字符预算和后续 Token 裁剪结果。

新增生成后的来源选择能力：

- 输入模型回答和全部候选来源。
- 输出最终返回给调用方的来源列表。
- 不查询数据库，不触发新的模型或 Embedding 调用。

`SourceCitation` 新增：

- `reference_index`：本次上下文中的 1-based 参考编号。
- `excerpt`：实际进入 Prompt 的 chunk 内容摘要，最多 200 字符。

`excerpt` 必须来自实际注入上下文的内容。若 chunk 在上下文预算阶段被截断，摘要不能展示未提供给模型的后续文本。

#### 来源分支矩阵

| 回答状态 | 最终 sources | hit_count |
| --- | --- | --- |
| 有一个或多个有效引用 | 只返回有效引用对应来源，按引用首次出现顺序排列 | `len(sources)` |
| 有效与无效引用混合 | 忽略无效引用，只返回有效来源 | `len(sources)` |
| 存在引用标记但全部无效 | 返回空来源，记录警告 | `0` |
| 正常回答完全没有引用标记 | 返回全部实际参考来源 | `len(all_sources)` |
| 明确拒答 | 返回空来源，不执行兜底 | `0` |

无效引用不能导致数组越界、异常响应或主链路失败。

### 5.4 HallucinationChecker

建议新增：

```plain
app/services/hallucination_checker.py
```

职责：

- 使用当前 `chat_model` 判断回答事实是否能在参考内容中找到依据。
- 返回结构化评估结果，不修改原回答。
- 记录额外生成 Token、评估耗时和状态。
- 超时、模型异常或格式异常时返回 `error` 状态，不向上抛出影响主链路的异常。

建议的内部结果语义：

```plain
status: faithful | unfaithful | error
score: 0.0 ~ 1.0；error 时为空
reason: 简短原因；不得包含完整敏感上下文
elapsed_ms: 评估耗时
```

模型输出仍可沿用参考资料中的严格文本格式：

```plain
忠实性分数：0-10 的整数
是否忠实：是/否
理由：一句话说明
```

解析时应允许全角或半角冒号，但不对任意自然语言做猜测。格式不完整直接记为 `error`。

### 5.5 抽样策略

抽样逻辑由 V4 编排层控制，而不是写入 `HallucinationChecker` 的 Prompt。

建议配置：

```plain
rag_faithfulness_sample_rate = 0.2
rag_faithfulness_timeout_seconds = 5.0
rag_query_pipeline = "v4"
```

约束：

- 抽样率必须在 `0.0 ~ 1.0`。
- `0` 表示关闭，`1` 表示全量执行。
- 超时必须为正数。
- 抽样未命中时不调用模型，内部统计状态为 `skipped`。
- 评估调用不重试，避免质量观测放大延迟和成本。

### 5.6 V4 编排接入顺序

`RagQueryServiceV4.query()` 后续按以下顺序演进：

1. 保持现有检索、精排、过滤和裁剪流程不变。
2. `SourceBuilder` 构建 context 和全部候选来源。
3. 使用 V4 专用引用 Prompt 生成回答。
4. 判断模型是否给出明确拒答；若是，立即返回固定拒答和空来源。
5. 解析引用并构建最终来源列表。
6. 按抽样率决定是否执行忠实性评估。
7. 评估为 `unfaithful` 时记录警告和指标，但仍返回原回答。
8. 评估为 `error` 时记录错误分类，但仍返回原回答。
9. `hit_count` 始终等于最终 `sources` 数量。

引用来源必须在回答生成后确定，不能继续沿用“生成前直接返回全部来源”的现有顺序。

## 6. 拒答语义

以下确定性条件继续直接拒答，不进入回答模型或不继续后处理：

- 检索无结果。
- Reranker 成功后所有候选均低于置信度阈值。
- Token 裁剪后无可用 chunk。
- SourceBuilder 无法构建有效上下文。

新增模型生成后的拒答识别：

- 当回答明确表达“在知识库中未找到相关内容”时，统一使用项目固定拒答文案。
- 拒答响应不返回候选来源。
- 拒答响应不执行忠实性评估，避免为无事实答案增加成本。

拒答识别只匹配项目明确要求的拒答语义，不应把包含“未找到某个次要信息”的正常回答整体误判为拒答。

## 7. 可观测性与隐私

### 7.1 指标

建议记录：

- 引用解析结果：`exact`、`fallback_all`、`all_invalid`、`refusal`。
- 有效引用数量和无效引用数量。
- 忠实性评估状态：`faithful`、`unfaithful`、`error`、`skipped`。
- 忠实性分数分布。
- 忠实性评估耗时。
- 抽样命中次数和总查询次数。
- 忠实性评估额外生成 Token。

现有 `TokenMetrics.record_generation_tokens()` 可通过独立 `source` 标签区分普通回答和忠实性评估；Redis 仍可保留用户维度的生成 Token 汇总，不要求本阶段新增持久化结构。

### 7.2 日志

日志允许记录：

- 用户和知识库标识。
- 引用数量、无效编号数量、评估状态、分数、耗时和错误分类。
- 问题长度、回答长度和上下文长度。

日志禁止记录：

- 完整问题、完整回答和完整参考内容。
- 文档正文、访问密钥、连接串和模型鉴权信息。
- 忠实性评估 Prompt 全文。

## 8. 数据与 API 影响

### 8.1 API

公开查询路径保持不变：

```plain
POST /api/v1/rag/query
```

`RagQueryResponse` 顶层字段保持：

```plain
answer
sources
hit_count
latency_ms
```

不增加 `faithfulness_score`、评估状态或清理引用后的答案字段。

`SourceCitation` 增加 `reference_index` 和 `excerpt`，属于向后兼容的字段扩展。

### 8.2 数据库

本阶段不修改表结构，不新增迁移，也不写入 `rag_evaluation` 或会话消息表。

### 8.3 依赖

本阶段使用 Python 标准库、现有 LangChain 聊天模型和现有指标能力，不计划新增第三方依赖。

## 9. 测试计划

测试通过公共服务接口验证行为，不为测试增加生产分支。

### 9.1 CitationParser

- 解析标准单引用。
- 解析连续多引用。
- 解析裸 `[参考N]`。
- 重复编号去重并保持首次出现顺序。
- 无引用返回空编号列表。
- 少量允许空白能够解析。
- 普通数字和非标准格式不会被误识别。

### 9.2 SourceBuilder

- context 编号与 `reference_index` 一致。
- `excerpt` 不超过 200 字符。
- 截断 chunk 的 excerpt 只包含实际注入内容。
- 有效引用只返回对应来源。
- 混合编号忽略无效引用。
- 全部无效编号返回空来源。
- 完全无标注返回全部来源。
- 来源去重且顺序稳定。
- 无效编号不会抛出异常。

### 9.3 V4 Prompt

- 包含仅根据参考内容回答的约束。
- 包含标准引用格式示例。
- 包含未找到时拒答规则。
- 包含步骤和列表完整性规则。
- V1-V3 仍使用原有 Prompt。

### 9.4 HallucinationChecker

- 正确解析忠实回答、分数和理由。
- 正确解析不忠实回答。
- 格式缺失返回 `error` 和空分数。
- 模型调用异常返回 `error`。
- 超时在配置上限内结束并返回 `error`。
- 不执行内部重试。
- 正确记录额外生成 Token。

### 9.5 V4 编排

- 正常引用只返回被引用来源。
- 无标注回答兜底全部来源。
- 混合有效与无效编号只返回有效来源。
- 全部无效编号正常返回回答和空来源。
- 模型明确拒答时返回固定拒答、空来源并跳过评估。
- 抽样未命中时不调用评估模型。
- 抽样命中时调用评估模型。
- `unfaithful` 只记录，不改变回答。
- `error` 不影响回答。
- `hit_count` 始终等于最终来源数量。
- 原有无召回、低置信度、空上下文和 Reranker 降级行为保持不变。

### 9.6 配置与 API

- 默认管道为 V4。
- 抽样率默认 `0.2` 且拒绝越界值。
- 超时默认 5 秒且拒绝非正数。
- API 来源中包含 `reference_index` 和 `excerpt`。
- API 不暴露忠实性分数。

## 10. 推荐实施顺序

后续实现使用 TDD，以垂直切片推进：

1. 引用解析器：先锁定单引用、多引用、重复和格式兼容。
2. 来源字段：补充 `reference_index` 与 `excerpt`。
3. 来源筛选：实现有效、混合、全无效和无标注四类分支。
4. V4 Prompt：补齐逐事实引用和回答完整性规则。
5. 忠实性评估：实现结果解析、错误状态和 Token 记录。
6. 抽样与超时：加入配置和非阻断调用边界。
7. V4 编排：按目标顺序接入引用和评估。
8. API 与默认配置：扩展来源字段并将默认管道切到 V4。
9. 回归验证：运行相关测试、全量测试、Ruff 和 Mypy。

实现过程中不得为了兼容测试而增加仅测试使用的生产参数或绕过分支。

## 11. 验收标准

- 正常回答中的标准引用能够映射到准确的文档、知识库、chunk、页码或章节。
- 多个引用按回答首次出现顺序返回，不重复。
- 模型漏标引用时不增加额外调用，返回全部实际参考来源。
- 全部引用编号无效时不报错，回答正常返回且来源为空。
- 明确拒答时不附加来源，不执行忠实性评估。
- 回答包含流程或列表时，不得用空泛一句话替代参考内容中的具体条目。
- 忠实性评估按配置抽样，默认约 20%。
- 忠实性评估超时、失败或格式异常不影响用户回答。
- 不忠实评估结果可在日志和指标中识别，但首版不阻断答案。
- API 不暴露可能误导用户的忠实性分数。
- 权限硬过滤、Reranker 降级、Token 裁剪和原有拒答行为没有回归。
- 实施不引入新依赖、数据库迁移、公开端点或额外引用修复调用。
