# 05-索引管道建立与流程打通：初期理解版

本文保留 `docs/plans/05-索引管道建立与流程打通.md` 的核心内容，用更轻量的方式帮助初期理解索引管道。详细约束、验收场景和测试建议见 `docs/specs/10-索引管道建立spec.md`。

## 一句话目标

把一条已经存在的 `kb_document` 文档记录，经过下载、解析、分块、向量化和入库，变成可检索的 `kb_doc_chunk` 数据。

本阶段不做：

- 不做 FastAPI 路由层。
- 不做完整 MinIO 服务。
- 不新增 `DocumentService`。
- 不重写已完成的 `EmbeddingService`。
- 不做查询、RRF、Reranker 和回答生成。

## 总体流程

```plain
准备文档记录
  -> 测试、脚本或下一阶段上传接口创建 kb_document
  -> kb_document 包含 id / kb_id / minio_path / file_name
  -> 原始文件已在 MinIO 或测试 fake storage 中

提交索引任务
  -> IndexService.submit_index_task(doc_id)
  -> 创建 kb_index_task(status=PENDING)
  -> IndexService._launch_task(...) 投递后台任务

执行索引任务
  -> IndexService.run_task(task_id, doc_id)
  -> document = PROCESSING
  -> task = RUNNING
  -> MinioStorageService.download(minio_path)
  -> DocumentLoaderService 解析
  -> ChunkService 分块
  -> EmbeddingService 批量向量化
  -> ChunkRepository 批量写入 chunk
  -> 清理旧版本 chunk
  -> document = DONE
  -> task = DONE
```

失败路径：

```plain
任意阶段失败
  -> 记录失败阶段和 error_msg
  -> document = FAILED
  -> task = FAILED
  -> 可重试错误进入延迟重试
  -> 不可重试错误等待人工处理
```

## 模块职责

### IndexService

索引管道的主编排服务。

负责：

- `submit_index_task(doc_id)`：创建索引任务并投递。
- `run_task(task_id, doc_id)`：执行下载、解析、分块、embedding、chunk 入库。
- `_launch_task(task_id, doc_id)`：本阶段用 `asyncio.create_task(...)` 做本地后台投递。
- `_schedule_retry(...)` / `_delayed_retry(...)`：按指数退避延迟后重新投递。
- 更新 `kb_document` 和 `kb_index_task` 状态。
- 处理失败、重试和版本切换。

不负责：

- HTTP 入参。
- 文件上传。
- Embedding 缓存细节。
- 查询和回答生成。

本阶段不单独保留 `IndexTaskLauncher`。Python / FastAPI 没有 Spring AOP 的 `@Async` 自调用问题，任务投递先放在 `IndexService` 内部。后续如果真的接 Celery / Dramatiq，再重新抽 `TaskDispatcher` 或 `IndexTaskLauncher`。

### MinioStorageService

本阶段只需要一个最小签名：

```python
async def download(object_key: str) -> bytes:
    ...
```

完整上传、删除、bucket 管理、object key 生成下一阶段做。

### Repository

`DocumentRepository`：

- 读取文档记录。
- 更新文档状态、版本、chunk 数、token 数和错误信息。

`IndexTaskRepository`：

- 创建任务。
- 更新任务状态。
- 增加重试次数。
- 记录失败信息。

`ChunkRepository`：

- 批量写入 chunk。
- 清理旧版本 chunk。

### EmbeddingService

已完成，本阶段只调用：

```python
vectors = await embedding_service.embed_documents(texts)
```

必须保证：

- `texts[i]` 对应 `vectors[i]`。
- 向量数量等于 chunk 数量。
- Embedding 失败时索引失败，不写零向量。

## 状态流

文档状态：

```plain
PENDING -> PROCESSING -> DONE
                    \-> FAILED
```

任务状态：

```plain
PENDING -> RUNNING -> DONE
                 \-> FAILED
```

自动重试时：

```plain
FAILED
  -> retry_count + 1
  -> PENDING
  -> 延迟后重新投递
```

## 延迟重试

参考原实现：

```plain
失败
  -> task.retry_count + 1
  -> task.status = PENDING
  -> delay_seconds = 2 ** (retry_count - 1)
  -> asyncio.create_task(_delayed_retry(...))
  -> _delayed_retry 内部 await asyncio.sleep(delay_seconds)
  -> IndexService._launch_task(...) 重新投递
```

理解重点：

- 不在索引执行线程里 `sleep`。
- 等待重试不占用真正干活的线程。
- MinIO 文件已经持久化，所以 MinIO 任务可以重试。
- 内存文本没有持久化，所以内存文本任务不自动重试。

## 版本策略

重建索引时不能先删旧数据。

正确顺序：

```plain
计算 new_version
  -> 写入 new_version chunk
  -> 新 chunk 全部写入成功
  -> document.version = new_version
  -> 清理旧版本 chunk
```

目标：

- 新版本失败时，旧版本仍可用。
- 避免查询出现“旧的没了，新的没写完”的断档。
