# 按模型、Token 类型和知识库导出 Token 监控指标

Token 监控指标通过 Prometheus/Grafana 提供运行观测，并使用 `model`、`token_type` 和现有知识库范围的 `kb_id` 作为标签。`kb_id` 当前只有 4 个值，因此接受其作为受控的低基数维度；这里的 `kb_id` 复用知识库级逻辑隔离，不引入独立 `tenant_id`，也不把用户 ID、部门 ID、请求 ID、问题或文档标识作为标签。单知识库请求使用真实 `kb_id`，多知识库请求使用 `kb_id="multi"`，不复制或按比例估算归属。`token_type` 使用互斥统计桶：`embedding` 表示 Embedding 输入，`input` 表示聊天模型的 System Prompt、用户问题、对话历史和检索上下文输入，`answer_generation`、`intent`、`hyde` 和 `faithfulness_check` 分别表示对应模型输出（`intent` 为意图识别分类输出，追问改写输出仍归入 `hyde`），`reranker` 表示 provider 返回的 Reranker 用量。应用内 Token 指标直接使用现有 `prometheus_client` 默认 registry，由既有 `/metrics` 端点暴露；不为本模块新增 OpenTelemetry Prometheus exporter。七类在线请求 Token 同时按 `token_type` 写入当前用户 Redis 累计，不在 Redis 中按模型分桶，也不在 Redis 中存储金额；没有当前用户的离线调用不写入用户累计。新统计启用时使用新的 Redis 统计版本命名空间，旧字段不迁移、不计入新累计。费用是读取时按当前部署单价从 Token 派生的估值：单价不变时与逐次累加结果一致，单价变更后历史费用随新单价整体重估，不保留调用时刻的价格快照。认证接口 `/api/v1/stats/tokens` 返回七类 Token 和读取时派生的分类型费用与总费用，不再返回七类 Token 的算术总量；总费用取分项四位小数取整后之和，保证与展示卡片一致。成本使用 Embedding、聊天输入、聊天输出和 Reranker 四类当前部署单价，意图识别、HyDE 与忠实性检测复用聊天输出单价。当前 `.env` 已配置 Embedding 与聊天模型单价；Reranker 官方页面 [qwen3-rerank](https://bailian.console.aliyun.com/cn-beijing?tab=model#/model-market/detail/qwen3-rerank?serviceSite=asia-pacific-china) 标示为 0.5 元/百万 Token，折算为 0.0005 元/1K Token。用户成本依据当前部署单价估算，模型或单价变更后不保证历史累计成本账单级准确。Grafana/Prometheus 查询权限仅授予系统管理员与运维；当前阶段保留既有 `/metrics` 访问方式，不额外增加监控内网 ACL。全局每日金额预算默认 1.00 CNY，达到 80% 触发预警，达到 100% 拒绝后续新请求；已经开始的请求继续完成并可能造成可观测的少量超额；单次请求估算成本超过 0.01 CNY 触发异常预警。预算和单次请求告警只在 Prometheus/Grafana 展示状态，本期不接入邮件、钉钉、企业微信或 Webhook 通知。Redis 与 Prometheus 是独立观测出口，任一出口失败不阻断问答，也不保证两者原子一致。监控指标不替代用户账单视图。

Redis 计数依赖 AOF/RDB、复制和备份配置；即使使用原子递增，也不提供故障场景下的账单级不丢失或网络重试下的严格 exactly-once 语义。该模块接受 Redis 统计在灾难恢复或确认丢失时出现低估或重复的可能，并通过监控和运维持久化配置降低风险；若未来要求账单级准确性，需要另建持久化聚合或幂等事件记录。
