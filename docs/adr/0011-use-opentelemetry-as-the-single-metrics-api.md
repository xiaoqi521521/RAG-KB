# 统一使用 OpenTelemetry 作为唯一指标 API

应用内所有监控指标统一通过 OpenTelemetry API 记录，`opentelemetry-exporter-prometheus` 的 `PrometheusMetricReader`（关闭 scope_info 标签）负责把 OTel 指标转写进 `prometheus_client` 默认 registry，由 `/metrics` 普通路由输出 exposition；HTTP 请求埋点改用 `opentelemetry-instrumentation-fastapi`，移除 `prometheus-fastapi-instrumentator`。本决定取代 ADR 0006 中"Token 指标直接使用 `prometheus_client` 默认 registry、不为本模块新增 OTel Prometheus exporter"的部分：对外指标名与标签保持不变——OTel Counter 命名不带 `_total`，由 exporter 按 Prometheus 规范转写补齐（如 `rag_token_usage` 输出为 `rag_token_usage_total`），因此既有告警规则、Grafana 面板和 `/stats/usage/daily` 的 PromQL 均不需要修改；HTTP 指标名从 instrumentator 的 `http_request_*` 变为 `http_server_*` 语义（如 `http_server_duration_milliseconds`），当前无告警与面板引用这些指标。`enable_metrics` 关闭时不注册全局 MeterProvider，各模块回退 OTel no-op，记录调用仍然安全。`rag_token_write_failure` 由 `GlobalTokenBudgetGate` 创建并暴露给 `TokenUsageRecorder` 共享同一个 instrument，因为 OTel 不去重同名 instrument，重复创建会导致同名 metric family 重复导出、Prometheus 抓取冲突。

迁移中固化了三个 OTel Python 行为约束。其一，SDK 同步 Gauge 采用"采集即消费"语义（`_LastValueAggregation.collect` 读取后置空），Prometheus 周期抓取在两次更新之间会丢失序列，预算 80% 告警依赖的 `rag_token_budget_used_cny` 与 `rag_token_budget_limit_cny` 因此改用 ObservableGauge，每次采集回调重新产出当前内存值，保证空闲期序列稳定存在。其二，OTel 的 `create_counter`/`create_histogram` 第二个位置参数是 `unit` 而非 `description`，描述文本必须以 `description=` 关键字传入，否则 exporter 会把无法映射的 unit 拼进指标名。其三，`PrometheusMetricReader` 官方不支持 multiprocessing，部署保持 uvicorn 单 worker；引入多 worker 前需要另行评估。faithfulness 抽样评估的三个 OTel 指标（评估次数、分数、耗时）在本次一并移除——它们此前未接 reader、从未实际导出，观测依赖保留的结构化日志，`faithfulness_check` Token 桶的计量与预算路径不受影响。`rag_token_request_cost_cny` 直方图桶从 prometheus_client 默认值变为 OTel 默认值（0 到 10000），该指标当前没有告警或面板消费。

后续按"只保留有消费者的指标"做了一轮精简：删除无消费者的 `rag_token_request_cost_cny` 直方图、静态配置值 `rag_token_budget_limit_cny` 和与"比例 ≥100% 告警"重复的 `rag_token_budget_rejected_total`；预算使用比例改为应用内 ObservableGauge `rag_token_budget_usage_ratio` 直接导出，告警规则不再需要 record 计算。OTel FastAPI HTTP 埋点整组移除（指标不在看板、且存活探测由 `up` 承担），`/metrics` 启动时注销 GC/平台/进程默认 collector 并关闭 `target_info`，最终只导出 `rag_token_*` 业务指标。看板从 12 面板收敛为 7 面板，告警从 5 条收敛为 4 条（保留 AGENTS.md 要求的预算 80%/100% 与单次成本告警，外加统计出口写失败）。

`/stats/usage/daily` 后续改为从 Redis 读取权威每日用量：应用在统一 Token 记录入口用 `HINCRBY` 累计 `rag:token:v3:daily:{yyyy}:{mm}:{yyyy-mm-dd}`，字段为 7 个非评估 `token_type` 桶；离线索引和线上问答的统一入口都会计入，但正式评估 run 的 RAG 执行与 RAGAS 判定不写入该 Hash，也不使用 `evaluationTokens` 字段。每日 key 与预算 key 使用同一部署时区并永久保留，金额仍在读取时按当前单价派生；评估 run 完整消耗只从 `kb_eval_run_usage` 汇总读取。对外 `tokens` 与 `cost` 是 Redis 非评估结果加数据库评估汇总的全口径，`evaluation_tokens` 与 `evaluation_cost` 继续单独拆分来源，两者在同一响应中不重复计数。Prometheus 不再作为每日用量历史来源，应用侧相关查询配置移除；Prometheus/Grafana 分维曲线继续作为运维观测，接受 counter 进程重启和序列过期带来的局部缺口。

Grafana 的今日 Token 与预算 Stat 面板读取 `rag_daily_usage_tokens` 和 `rag_daily_usage_cost_cny`。Prometheus 抓取 `/metrics` 时，应用先调用前端全局用量页同一个 `UsageHistoryService` 读取当日 Redis 非评估消耗和数据库评估 run 汇总，再刷新这两个低基数 Gauge；标签只保留 `scope="global"`。Prometheus Counter 的 `increase()` 不再用于手工拼出全口径当日 Token 或预算，避免新 counter 序列、进程重启和窗口截断导致与前端聚合不一致。

Prometheus 观测明确拆分线上与评估两个口径：`rag_token_usage_total` 及其成本指标只承接线上管道七类消耗；整轮评估中的 RAG 执行与 RAGAS 判定按真实阶段写入 `rag_evaluation_token_usage_total` 和 `rag_evaluation_token_usage_cost_cny_total`，仍使用 `model`、`token_type`、`kb_id` 受控低基数标签。评估 RAG 执行沿用 `input`、`embedding` 等阶段桶；RAGAS 判定的输入、输出和向量消耗分别使用 `ragas_input`、`ragas_evaluation` 和 `ragas_embedding`，避免同名桶混合两个来源。全局每日 Hash 明确排除全部评估消耗，避免分类型日总量和数据库评估 run 汇总重复计数；历史 Hash 中已存在的旧 `evaluationTokens` 字段只被读取器忽略。评估成本面板直接使用分阶段成本指标，与检索问答成本面板保持同一展示方式；run 结算成本 `rag_evaluation_run_cost_cny_total` 没有独立消费价值，不再导出。这些指标仍是 Prometheus 观测 counter，继承进程重启后的局部缺口限制，历史通用序列中的旧评估样本不回溯改写。

Redis 写超时不作为确认写失败计量：`rag_token_write_failure` 只统计连接异常、Redis 错误或本地指标写入异常等确认失败；超过写入 SLA 的 Redis 调用只输出结构化日志并明确最终结果未知。Redis 收到命令后仍可能在客户端超时后完成写入，因此超时不能混入失败指标。`GlobalTokenBudgetGate` 继续创建共享失败 instrument 并交给 `TokenUsageRecorder`，避免 OTel 同名 metric family 冲突。

失败来源标签使用 `component` 而不是 `token_type`：Token 统计出口失败时 `component` 记录具体 Token 桶，预算 Redis 失败时固定为 `budget`，避免把预算组件误读成一种 Token 类型。该标签只有固定低基数取值，不包含用户、部门、知识库、请求或文档标识；旧样本中的 `token_type` 失败标签不回溯改写。

后续按"只保留有消费者的指标"继续精简：预算绝对值 `rag_token_budget_used_cny` 没有面板或告警直接消费，改为保留应用内已用金额并只导出 `rag_token_budget_usage_ratio`；RAGAS 单项结果、重试和耗时 `rag.evaluation.ragas.*` 同样没有看板或告警消费，改为依赖保留的结构化日志。删除这些指标不影响预算闸门、评估费用统计和 RAGAS 执行流程。
