# 保持显式对话服务编排，不引入 LangGraph

本阶段继续由显式服务层编排意图识别、权限、缓存、RAG、生成、SSE 和会话持久化，不引入 LangGraph。新增意图识别只是一次模型分类调用和确定性分支，尚不足以抵消图状态、节点依赖注入、流式适配和测试复杂度的成本。

## Considered Options

- 引入 LangGraph 统一承载所有聊天步骤：暂不采用。它更适合长时、有状态、可恢复、人工介入或动态循环的 agent 工作流；本项目当前业务状态和会话历史已有数据库及服务层边界。
- 保持显式服务编排并抽象意图识别、意图执行接口：采用。未来出现复杂循环、人工审核、可恢复长流程或动态 Agent 路由时，可基于这些边界重新评估迁移。

## Consequences

- LangGraph 的 checkpointer 不替代现有按用户隔离的数据库会话存储。
- 同步和 SSE 可以共享分类及分支契约，同时保留各自已有的输出和异常语义。
- 后续若引入 LangGraph，应单独评估状态持久化、权限边界、预算闸门、取消语义和 SSE 事件映射，而不能仅把现有方法机械包装成节点。
