# 在混合检索层过滤授权范围

route 层继续对多知识库请求执行全量读权限校验：任一知识库无权时整体返回 `403`。同时，`HybridRetriever` 提供受保护的检索入口，从当前请求 `ContextVar` 读取用户并复用 `PermissionService` 逐库计算 `allowed_kb_ids`，过滤无权范围后才执行混合检索；过滤后的范围也传递给 v3/v4 的 HyDE 向量检索。原始检索方法只作为内部实现，不作为业务入口。

该双层边界保留了当前 API 的整体拒绝语义，并使混合检索在被独立调用时仍能拒绝式执行权限过滤。权限规则只由 `PermissionService` 维护，检索层不直接复制用户、部门和公开知识库的授权判断。

检索层过滤产生的专用审计日志允许记录当前 `user_id` 和被过滤的 `denied_kb_ids`，但不允许将这些标识写入指标标签或扩展到其他权限、认证日志。

## Consequences

- route 层和检索层的职责不同：前者保护请求语义，后者保护实际检索范围。
- 混合检索过滤后的空范围返回 `403`，权限数据源不可用返回 `503`；不存在或已删除的知识库在检索过滤中被排除。
- `ContextVar` 未初始化时受保护入口返回 `401`；请求范围去重并保持首次出现顺序。
- v1 直接向量检索不新增该 HybridRetriever 内部过滤；其在线调用仍依赖 route 层校验。
