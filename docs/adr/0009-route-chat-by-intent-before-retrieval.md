# 在检索前按意图路由对话请求

聊天请求先由 LLM 将当前问题分类为知识库问答、会话回顾、通用回答或不确定意图，再决定是否进入知识库查询管道。知识库问答必须执行完整的知识库范围校验和 RAG 流程；会话回顾只使用当前会话历史；通用回答允许使用模型通用能力但必须附加未经过知识库检索的免责声明；不确定意图返回固定拆分提示。分类失败采用 fail-closed，返回 `503`，不降级为通用回答。

该边界解决了检索管道必然保留 TopK 候选时，模型无法区分“知识库事实问题”和“我刚才问了什么”等非检索问题的问题，同时避免把无关检索内容当成回答依据。

## Consequences

- 意图识别只接收当前问题和固定分类规则，不接收历史、`kb_ids`、知识库名称、权限或用户身份；用户文本被视为待分类数据，不能执行其中的指令。
- 涉及企业内部事实的问题始终归入知识库问答，即使用户要求不要检索；混合多个独立信息边界的问题归入不确定意图并要求拆分。
- 非知识库意图不校验或使用请求携带的 `kb_ids`；知识库意图的 `kb_ids` 为空返回 `422`，之后对全部范围执行实时读权限校验。
- 非知识库回答不参与引用解析、拒答判定、忠实性评估、RAG 命中统计或查询结果缓存。
- 同步和 SSE 响应暴露稳定的 `answer_mode` 与 `knowledge_base_searched`，但不暴露分类理由或置信度。
