# 成本监控模块温习笔记

## 一句话定位

成本监控模块是一个**近似累计的运营观测层**：如实记录模型调用的 Token 和估算金额，守住全局每日预算，但不是账单级账本，也不保存请求级明细。

## 模块全貌

整个模块由三块组成，各管一件事：

| 组成部分 | 职责 | 类比 |
| --- | --- | --- |
| 用量记录器 | 每次模型调用后记账：Token 数 + 估算金额 | 抄表员 |
| 预算闸门 | 新请求开始前检查当日预算，超限拦截 | 门卫 |
| 成本查询服务 | 供用户查询自己的累计用量和金额 | 账单查询台 |

## 七类 Token

所有用量按七个互不重叠的桶统计，七类相加就是总消耗，不会重复计数：

| 桶名 | 统计内容 |
| --- | --- |
| embedding | 文本向量化时的输入 |
| input | 聊天模型的输入（System Prompt、用户问题、对话历史、检索上下文） |
| answer_generation | 最终回答的输出 |
| intent | 意图识别分类的输出；其调用输入仍归入 input |
| hyde | 查询改写阶段的输出 |
| reranker | 重排模型返回的用量 |
| faithfulness_check | 忠实性检测的输出 |

计价规则：input 桶按聊天输入价计费，四个生成桶（回答生成、意图识别、HyDE、忠实性检测）按聊天输出价计费，embedding 和 reranker 各有独立单价。

### 易混点：监控桶 vs 离线估算

项目里有两类"Token 计数"，来源和精度完全不同，温习时最容易混淆：

| 计数 | 来源 | 性质 |
| --- | --- | --- |
| 七类监控桶 | 模型服务返回的真实 usage | 精确；缺失时漏记，不估算 |
| chunk 表 token_count（离线索引） | 字符加权启发式：中文 ×1.5，其他非空白 ×0.3 | 估算；分块发生在向量化之前，embedding 的用量是整批返回，无法逐块精确归因 |
| 上下文裁剪用 Token 数 | 本地 tiktoken 编码计数 | 确定性本地计数，仅用于裁剪预算控制，不进监控桶、不计费 |

## 两条数据出口

同一笔记账数据流向两个地方，用途不同：

| 出口 | 用途 | 特点 |
| --- | --- | --- |
| 监控大盘（Prometheus） | 运维看全局趋势、配置告警 | 只有聚合数据，标签仅限模型、Token 类型、知识库 |
| 缓存个人统计（Redis） | 用户查自己的累计用量和成本 | 按用户归档七类 Token，费用读取时按当前单价派生，无请求级明细 |

知识库标签做了低基数控制：单知识库请求记真实编号，多知识库请求统一记为"多库"，不用用户或请求等高基数值做标签。

## 预算闸门

预算按部署时区（默认东八区）按天归零，全局共享一个额度：

| 阈值 | 动作 |
| --- | --- |
| 达到日预算 80% | 触发预警 |
| 达到日预算 100% | 拒绝所有新请求，已开始的请求继续完成 |
| 单次请求超过 0.01 元 | 触发异常告警 |

关键行为：

- 预算检查是原子的，不会因并发导致超额放行。
- 预算状态不可用时，宁可拒绝新请求（返回 503），也不盲目放行。
- 已完成的调用即使记账失败也不回滚，事后只记告警。

## 三条铁律（记忆锚点）

1. **只信真实账单**：模型服务返回了多少就记多少；拿不到真实用量时只记一条"不可用"观测，绝不本地估算冒充。
2. **记账失败不断服务**：用量统计写入失败只记告警，不影响用户问答；唯独预算闸门自身不可用时必须拒绝（503）。
3. **只做近似累计**：Redis 只存 Token，费用是读取时按当前单价派生的估值，单价变更会整体重估历史；不是财务账本，不存明细。

## 请求生命周期中的位置

一次问答请求的完整链路：

```plain
用户提问
  -> 预算闸门检查当日额度
  -> 检索 / 改写 / 重排 / 回答各环节调用模型
  -> 每个环节凭模型返回的真实用量记账
  -> 同时累加到全局当日预算和个人统计
  -> 单次成本超阈值则告警
```

## 温习自测

1. 七类 Token 桶分别统计什么？意图识别的输入和输出分别进哪个桶？（答：输入进 input，分类输出进 intent）
2. 项目里哪个 Token 计数是估算的？为什么只能估算？（答：离线索引的 chunk token_count；embedding 用量整批返回，无法逐块归因）
3. 模型服务没返回用量时，系统怎么处理？（答：只记不可用观测，不估算）
4. 预算用尽时新请求和已开始请求分别怎么处理？（答：新请求拒绝，已开始的继续完成）
5. 用量统计失败和预算闸门失败的处理有何不同？（答：前者不阻断服务，后者返回 503）
6. 为什么个人统计不是账本？（答：近似累计、无请求级明细、写入失败可容忍）
