# 文档重建不影响查询方案总结

问题：文档替换或重建索引期间，用户不能查询旧版本内容

解决方案：
先重建新版本索引，成功后再更新文档表：重建时不把当前 DONE 文档改成 PENDING，不提前覆盖 file_name、minio_path、version；新 chunk 写入新 doc_version，旧 chunk 保留可查。任务成功后，在事务中切换文档版本与文件元数据，再清理旧版本 chunk。

方案抉择：
- 索引任务表新增列 payload 存临时文件信息最可靠，但会改表；本项目采用。
- MinIO 路径根据索引任务规则化，kb/{知识库ID}/staging/{文档ID}/{任务ID}-{文件名}，修改原先路径使用kb_id+UUID-文件名，缺点是与索引任务信息强绑定，假设索引任务失败，文件可能会变成孤儿文件或者难以重新定位
- 把 MinIO 路径放在代码变量里，等索引成功后再用它更新 kb_document.minio_path，但是索引任务是异步任务，不可靠，服务重启会丢失
- Redis 或内存可避免改表，但容易丢失；
- 插入新文档再删旧文档隔离性好，却会改变 document_id，影响引用、历史记录和审计记录。
